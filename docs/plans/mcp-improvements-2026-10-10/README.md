# MCP 개선 작업 패키지

준비일: 2026-10-10 KST. 기준 commit: `e75d99a2bf1fe8deb0e5e6d94d81b011b460da42`.

32개 개선 항목을 준비했다. P0 8개, P1 19개, P2 5개다. 각 항목에는 근거, 변경 범위, 의존성, 수용 기준이 있다. 첫 구현 범위 MCP-08 → MCP-04는 제품 구현과 격리 시험을 진행 중이다. 나머지 항목은 계획 상태다. 배포한 결과가 아니다.

현재 실행 추적 강제, exec/run 중복 방지, context 요약, 증분 출력, 배포 전 active-process guard는 이미 있다. 이 기능을 다시 만드는 항목은 제외했다. 현재 공백과 추가 기능을 [기준·근거](BASELINE.md)에서 구분한다.

## 우선순위

P0는 오래된 단계 복원, 중복 변경, 잘못된 완료 판정을 막는다. P1은 호출 수, 출력 크기, 관찰 공백과 배포 검증을 개선한다. P2는 장기 운영과 지원 확인이 필요한 확장이다. S/M/L은 상대 변경 규모다. 일정 추정값이 아니다.

첫 작업 묶음은 저장 스키마와 transaction 기반, 응답 예산, 도구·환경 진단이다. 다음 묶음에서 단계·근거·변경 receipt를 연결한다. 정확한 순서는 [실행 문서](EXECUTION.md)를 따른다.

## GPT와 MCP의 역할

서버는 저장 상태, 실행 결과, 중복 방지와 작은 조회를 책임진다. GPT는 목표 해석, 다음 단계 선택과 사용자 확인을 책임진다. 프로젝트의 기존 계약과 외부 완료 권한은 보존한다.

브라우저 반복 감시의 대체 후보는 MCP Events다. 지원 surface와 SDK 호환성 검증을 먼저 수행한다. 일반 ChatGPT 대화의 끊긴 stream을 복구한다는 전제는 두지 않는다. [공식 MCP Events 문서](https://developers.openai.com/plugins/build/mcp-events)를 기준으로 MCP-29~31을 준비했다.

기존 `chrome-mcp`, `mcp-2` 자동화는 PAUSED 상태를 유지한다. 이 준비 작업에서는 자동화, consumer 작업, Docker, Git commit/push를 변경하지 않았다.
