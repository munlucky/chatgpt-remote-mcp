# GPT 프로젝트 지침: MCP 작업 복구

이 지침은 `chatgpt-remote-mcp`의 작업 조회와 실행 도구에 적용한다.

1. 프로젝트 작업을 시작하거나 이어갈 때 `get_work_context`를 먼저 호출한다. 정확한 `cwd` 또는 기존 `taskId`를 사용한다. 다른 프로젝트의 작업을 선택하지 않는다.
2. 활성 작업이 있으면 같은 작업을 사용한다. 없을 때만 `checkpoint_work(mode=create)`로 짧은 작업 목표와 미완료 단계를 저장한다. 기존 프로젝트 계약이나 Kernel 작업 계약은 재발급하지 않는다.
3. 명령과 스크립트에는 `taskId`와 `operationId`를 함께 지정한다. 같은 실행의 재시도에는 같은 `operationId`와 같은 실행 입력을 사용한다. 조회 옵션 변경은 실행 입력 변경이 아니다. 다른 작업을 실행할 때만 새 ID를 사용한다.
4. `prepared`, `running`, `unknown` 실행을 새 ID로 반복하지 않는다. `running`이면 기존 프로세스를 조회한다. `unknown`이면 현재 저장소와 증거를 확인하고 명시적으로 판단을 기록한다.
5. 결과의 `nextCall`을 조회 안내로 사용한다. `read_process`에는 이전 결과의 `nextSeq`를 `afterSeq`로 전달한다. 응답을 잃어서 커서를 모르면 `afterSeq=0`으로 남아 있는 출력을 조회한다. `availableThroughSeq`를 읽은 커서로 사용하지 않는다.
6. 프로세스가 끝나도 `hasMore=true`이면 남은 출력을 읽는다. 종료 코드 0만으로 전체 작업을 완료했다고 판단하지 않는다.
7. 단계의 검증이 끝나면 `checkpoint_work(mode=update)`로 완료 사항, 남은 사항, 변경 경로, 증거 참조를 갱신한다. 기존 revision을 사용한다. revision 충돌이면 현재 상태를 다시 읽는다.
8. 기본 조회는 요약이다. 상세 대조에는 `get_work_context(format=full)`을 사용한다. 요약 누락, 불완전한 저장소 관찰, 오래된 검증 결과를 실행 승인이나 완료 증거로 사용하지 않는다.
9. 프로세스 상태만 필요하면 `list_processes`에 `taskId`를 지정한다. 명령 본문은 요청하지 않는다. 사용자 입력이나 승인 대기를 임의로 넘기지 않는다.
10. 현재 파일과 마지막 검증을 대조한 뒤 원래 요청이 모두 끝났을 때만 `complete_work`를 호출한다. 미완료 단계가 있으면 완료된 변경과 실행을 반복하지 말고 그 단계부터 진행한다.

서버가 `tracking_required`를 반환하면 실행은 시작되지 않았다. 오류가 안내한
작업 조회를 먼저 수행한다. 파일 편집과 stdin 입력에는 이 중복 방지가 적용되지
않으므로 현재 내용을 확인한 뒤 필요한 변경만 수행한다.

이 지침은 GPT의 응답 스트림 오류를 고치거나 유휴 대화를 자동으로 깨우지 않는다.
다시 연결됐을 때 기존 작업과 실행 결과를 확인하는 절차다. 추적 없이 이미 실행한
명령에는 소급해서 실행 기록을 만들지 않는다.
